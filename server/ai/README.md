# Harry Messenger AI context

`harry-system-prompt.md` is the public, version-controlled base prompt for the server-side Harry Messenger integration.

## Integration order

At request time, `openai-chat-service.mjs` constructs the model input in this order:

1. The complete contents of `harry-system-prompt.md` as the system message.
2. An optional server-private profile overlay as trusted system context.
3. Optional live portfolio facts generated by the server from verified data.
4. A bounded, explicitly untrusted conversation transcript.
5. The visitor's newest message.

Never send an API key or private profile overlay to the browser. The browser calls `/api/chat`; the Node server reads provider credentials and private context from files or environment variables outside the public `dist` directory. Client-supplied messages labeled as prior assistant replies remain untrusted data, preventing a forged browser transcript from gaining system-level authority.

## Server configuration

- `OPENAI_API_KEY` enables the endpoint and remains server-only.
- `OPENAI_MODEL` defaults to `gpt-5.6-sol`.
- `HARRY_PRIVATE_PROFILE_PATH` optionally points to a protected Markdown overlay.
- `CHAT_SAFETY_SALT` enables a privacy-preserving per-visitor safety identifier.
- `CHAT_DAILY_LIMIT` defaults to 100 provider calls per UTC day for the running process.
- `CHAT_CONCURRENCY_LIMIT` defaults to three simultaneous provider calls.

The provider request uses the Responses API with low reasoning effort, concise text verbosity, and Responses application-state storage disabled. OpenAI's applicable abuse-monitoring retention policy may still apply. The public endpoint validates message length, bounds context, applies per-visitor and global limits, and returns only safe error codes.

## Recommended private overlay

The public repository intentionally does not guess or store unconfirmed personal details. A private overlay can later add information Harry wants the assistant to know, such as:

- education and academic interests;
- current city or timezone at the desired level of precision;
- awards, publications, and verified project results;
- work and collaboration history;
- current goals and availability;
- preferred answers to personal questions;
- additional project milestones;
- response-style examples written by Harry.

Keep the private overlay in the existing server-only shared directory or another path outside the release and web roots. Do not commit it to Git and do not use a `VITE_` environment variable for its contents.

During local profile collection, `server/ai/harry-private-profile.md` is the ignored working copy. The production integration should read a protected copy such as `/www/wwwroot/harry.rosebeg.com/shared/harry-private-profile.md`, ideally configured through a server-only path variable such as `HARRY_PRIVATE_PROFILE_PATH`.

## Maintenance

Update the public prompt whenever `src/content/projects.ts`, `src/content/photos.ts`, `src/content/about.md`, or `src/content/contacts.ts` changes. Facts in the prompt should remain traceable to source-controlled portfolio data or an explicitly trusted private overlay.
